## 仕組み
- `tools/automesh.mjs`：透明部分の輪郭を追跡し、制約付きドロネー分割でメッシュを作る。目の縁・口角・毛先・裾は頂点を細かくする。
- `tools/build-rig.mjs`（`rig-builder.mjs`・`face-rig.mjs`）：ワープ・回転デフォーマの親子関係、パラメータごとのキーフォーム（変位関数から生成）、関節の2親混合、描画順の切替、物理を `hibiki.rig.json` に書き出す。
- テクスチャはミップマップと三線形補間で描き、縮小表示でも縁がざらつかない。
- `rig-eval.js`：キーフォームの多重線形補間、親子変形、減衰ばねの物理。`renderer.js`：PixiJS 8のMesh。部品の画像は `hibiki.rig.json` の `textureVersion`（全部品の画像のハッシュ。`rig-builder.mjs` が書く）を URL に付けて読むので、同じ名前のまま中身を更新しても古いキャッシュ（Safari・GitHub Pages）が使われない。透明部分を捨てるシェーダーでステンシルマスクを描き、虹彩を白目で、歯と舌を口内で切り抜く（既存V3のWebGL2描画の方式を引き継ぐ）。`motion.js`：呼吸・瞬き・視線・頭と体の追従・疑似発話・表情・身振り。
- 4つのポーズの身振りでは、クロスフェードも半透明の重ねも使わない。ふだんの腕を 0.42 秒で「接近姿勢」へ動かし、0.5 秒で 1 コマで描かれたポーズの腕に差し替える。接近姿勢は `tools/pose-enter.mjs` が、描かれた肘と手首の位置・手の向きに当てはめて決め、リグの `poseApproach` に書き出す。描かれた腕が手前に向いて短縮している所は、ふだんの腕も同じだけ短縮させる（`UpperShortR/L`：上腕を肩の支点で縮める、`ForeShortR/L`：前腕を肘で縮める。手と袖口は大きさを保つ）ので、ふだんの腕とポーズの腕の肩・肘・手首・手の向きが一致し、どちらも引き伸ばさない（差し出すポーズの右腕は上腕 0.48・前腕 0.35 まで縮む）。差し替えの瞬間、ポーズの腕は `PoseEnter` 0 の変形（層ごとのワープ格子。上腕・前腕・手のそれぞれを、描かれた関節からふだんの腕の関節へ写す相似変換を、各部分の軸からの距離で混ぜたもの。縮尺はほぼ 1）でふだんの腕に重なり、そこから 0.3 秒で描かれたポーズへほどける。戻るときは逆順（0.3 秒で畳み、1 コマでふだんの腕に戻し、0.45 秒で休め）。肘の範囲は −160 まで。手の形（開く・振る・指さし・握る）も 1 コマで切り替える（`HandFadeR/L` は 1 のまま）。顎のポーズの間は頭の揺れを抑える。差し出すポーズの右腕には ChatGPT の途中の絵（`Hibiki_V3_arm_R_midReach_R3_4096x6144.png`、監督確認で合格・条件付き）を使う。`tools/import-mid-reach.mjs` が、R3 に無い紺の肩ひもと肩の素肌を切り落とし、肩の支点で 1.06 倍にして外側へ 30° 回し（1.18 倍ではパフ袖が反対側の腕よりひと回り大きく見えた）（描かれたままでは手が体の中央に入り込み、休め→途中→完成で手が内へ入ってから外へ出るジグザグになるため、休めの手と完成形の手の間の軌道に乗せる）、肘で上下の層に分け（紺の前腕は肘の下 14〜34 単位を両方の層に入れ、下の層の上端はやわらかく消すので、二つの層が別々に変形しても肘に白いすき間が開かない） `parts/pose/reach_mid_*.png` に置く（元ファイルの SHA256・変換・関節はマニフェストの `poses.reach.mid`）。この腕は 2 段階でつなぐ：右のふだんの腕を接近姿勢（途中の絵の関節に当てはめ、短縮は上腕 0.8・前腕 0.75 まで）へ動かし、0.5 秒で 1 コマで途中の絵に差し替える（`PoseEnter` 0 で接近姿勢に乗り、0.5 で描かれたまま）。続けて `PoseEnter` 0.5 → 1 で途中の絵が完成形の関節へ向かって変形し（前腕が手前へ向いて縮む）、0.85 で 1 コマで完成形の腕（両腕）に差し替える（完成形の層は 0.5 で途中の絵の関節に、0.85 でその 3 割の位置に乗せてあるので、差し替えの瞬間に関節が一致する）。途中の絵の無い左腕は、その差し替えの直前に接近姿勢へ着き、差し替え後に残りをほどく。戻りは逆順（完成形 → 途中の絵 → ふだんの腕）。ふだんの腕の表示は `ArmsDefaultR/L` で片腕ずつ切り替える。これで、縮めて細くなった右腕のコマと引き伸ばした袖のコマは無い。 差し出すポーズの完成形は、描かれたままでは手が y 600（指先）まで下がりバストアップ（y 524 まで）では袖しか見えないため、肩から持ち上げた形（`pose-enter.mjs` の `LIFT`：肘 [372,418]・手首 [356,470]・指先 [334,518]）にしてある。上腕は少し外へ振れ、前腕と手は手前へ向く分だけ軸方向にだけ短縮し（幅は保つ）、手のひらが胸の下、指先が枠の中に収まる。途中の絵もこの形へほどける。
- 向きと視線（`app.js`・`motion.js`）：画面上のアバターの位置から、体と顔を画面の中央へ向ける（右にいれば左へ、左にいれば右へ、中央なら正面）。位置や画面の大きさが変わればその場で付け直す。PCはページのどこにあるマウスでも目で追い、頭も少しそちらへ向ける。スマホはページのどこをタップしてもその位置へ目線を向ける（リスナーは受け身で、スクロールやボタンは妨げない）。操作が止まって約3秒で、配置に応じた向きと自動の目配りに戻る。トップの「配置」で左・中央・右を切り替えて確かめられる。
- 身振りは人の動きの原則で作った：肩→肘（0.05秒後）→手首（0.1秒後）の順に動き出し、動き出す前に小さな逆向きの予備動作、動き始めと止まりの緩急、止まったあとの小さな行き過ぎと戻り（余韻）を入れる。手を振る動きは前腕と手首の小さな往復で、手首が前腕より遅れてついていく。振る手はR3の手を手首で左右反転して使い、上げたとき手のひらが正面・親指が体の中心側を向く。
- 体の向き（Live2Dと同じ階層）：体の回転（BodyAngleZ、腰が支点）→ 上半身のワープ（BodyAngleX・BodyAngleY・呼吸・肩すくめ）と下半身のワープ（LowerAngleX）→ 各部品。端の形（BodyAngleX ±10）は、Live2D のデモモデル（natori_pro_t06・mao_pro、公開 API で頂点を測った。`docs/live2d-demo-analysis-20261030.md`）に合わせた円柱の回り方：BodyAngleX 10 で胸の中心線は胴の半幅 a の 0.14 だけ向く側へ滑り、端は 0.03 だけ（断面全体がわずかに流れる）、間は放物線でつなぐ。手前側の面は端ほど伸び（約 11%）、奥側の面は端ほど縮む（約 11%）が折り返さない。せん断も上下の動きも無く、輪郭（端）は曲げない。高さごとの量は肩 0.85・胸 1・腰 0.5・尻 0.3・裾 0.25。首と襟の中央（中心線から 60 以内）は中心線の 3 分の 1 だけ動く（デモモデルの頭は胸の中心の 0.3〜0.5）。胸のリボンと飾りは面より 1.3 倍動く（視差）。腕は胴のワープの子ではなく、肩の支点の位置だけを胴の場（向き・傾き・呼吸・肩すくめ）から受け取る（上腕の上端は胴にブレンドして肩の継ぎ目を保つ）ので、向きで腕が縮むことがない。肩のフリルは下の肩の肌と同じ胴のワープだけで動く。縦のずれ（斜めの押しつぶし）は入れず、胸より上にだけ 2% の遠近（手前の肩がわずかに下がる）を置く。首と襟の中央（中心線から 60 以内）は形を保って中心線と一緒に動き、その外の肩は体と一緒に回る。腰から下（LowerAngleX）は動きの中で上半身に少し遅れて同じ向きに回る（腰で約半分）。脚は全身の Live2D モデルと同じく足元から向きを付ける（`leg_R_turn`・`leg_L_turn`、腰の支点）：奥側（向く側）の脚は 5% 細く、中央へ 12 寄って 6 上がり（後ろへ隠れる）、手前側の脚は 4% 大きく、4 外へ・4 下がって前に出る（重心が乗る）。両足のつま先は足首を支点にせん断で向く側へ最大 10° 開く。ブーツは正面の絵しかないので、はっきり斜めを向いたつま先はメッシュでは作れない。
- 顔の向き（Live2Dと同じ階層）：顔の回転（AngleZ、首の付け根が支点）→ 顔全体のXYワープ → パーツごとの変形。AngleX・AngleYでは、目・眉・口は形を保ったまま奥行き（口34・眉30・目28、輪郭0）に応じて平行移動し、奥の目はわずかに小さく、手前の目はわずかに大きくなる。肌（輪郭と鼻）だけをワープで丸く変形し（鼻が最も手前、輪郭は0）、向く側の輪郭は縮み反対側は広がる。肌と、その上に重なる前髪・横髪は、同じ「顔の面」（鼻が最も手前、顔の輪郭で0になめらかに落ちる奥行き）で動くので、髪が頬の上に乗ったり頬から離れたりしない。前髪は顔と同じかそれ以上に（毛先ほど手前に）ずれ、向いた側の横髪は少し多く頬を覆う方へ寄り、反対側の横髪は頬の外側の輪郭に残る。後ろ髪は少し遅れる。顔を30°向けると鼻は顔幅の約11%、上下30°で約7%動く（実測の目安：12%・7%）。横髪は原画Aでは顔より手前なので、目や口より手前に描く。前髪の左右の端は横髪と同じ奥行きにして、境目で切れないようにした。頭の下には、肌を横髪・頬・あご・耳の外側へ約30 px補間で広げた下地（head_under）を敷き、どの向きでも背景が見えない。鼻のハイライトは肌の一部として扱い、鼻と一緒に動く。肌の奥行きは顔の輪郭（鼻から左右に約130 px、あごまで約140 px）で0になり、頬とあごは横髪と一緒に動くので、向いても間に隠れていた肌が帯として開かない。横髪の下や首の横の補間した肌は、隣の見えている肌の色から外側ほど暗くなる陰影をつけた。 横髪の層は原画Aの肌との差分で切り出しているため、あご横の薄い髪は「肌を除いた色」（半透明の濃紺）を持ち、休めでは原画Aどおりに再合成されるが、下の肌が動いたりページの縮尺で小さく見えたりすると頬の横に黒い帯として見える。`tools/lighten-hair-inner.mjs` で、目より下・層の縁から 40 px 以内の暗い画素の色を、隣の不透明で光の当たった髪の色に 75% 寄せ、不透明度を上げた（記録は `parts/hair-inner.json`）。あご横の髪の内側は原画Aの光の入った明るい青になる。

- 切り抜きの縁（`tools/clean-edges.mjs`）：R3 の体・腕・袖・手とポーズの腕の部品は、縁の帯（透明に接する 1.6 px、ポーズの腕は 2.2 px）の画素の色を内側の不透明な画素の色で置き換え（切り口に混じった背景の暗い縁・灰色のにじみが消える）、アルファを少しなだらかにして約 0.3 px 内側へ詰める（鋸状の縁が 1 本のやわらかい線になる）。休めの手の画像に描かれていた袖口・袖の布（手首をひねると袖口の外に出る）は、肌でない色のまとまり（白・灰青・紺）のうち輪郭に接する 50 px 以上のものを取り除く。原画Aの顔・髪・口の中の部品は触らない。処理済みの記録は `parts/r3/clean.json`・`parts/pose/clean.json`。
- 手：身振りごとに、手のひらの向きと親指の側を人の体の動きとして決め、描かれた手をそのまま使うか手首で反転するかを選ぶ（振る・横へ差し出す・腰の前の両手・指さしは反転、休め・軽く握るはそのまま）。手の色は原画Aの頬と首の肌の平均に合わせ、反転した手は列ごとの明るさを元の向きに戻して光の向きを揃える（`tools/hand-tone.mjs`）。 休めの左手は ChatGPT の描き直し（`Hibiki_V3_hand_L_rest_finger_complete_R3_4096x6144.png`、監督確認で合格・条件付き。人差し指の外側まで欠けずに描かれ、R3 と同じ箱と手首の支点）を `tools/import-hand-l.mjs` で取り込んだ：R3 の箱で切り出し、肌の色の平均と広がりを置き換える前の R3 の手に合わせ（その後の色合わせは他の手と同じ）、手首に一緒に描かれていた白い袖口のフリルは `clean-edges.mjs` の手の処理で外す（リグの袖口の部品がその上に乗る）。元ファイルの SHA256 は `parts/r3/manifest.json` の `hand_L.source`。
- 瞬きは上まつ毛のメッシュを下まぶたへ曲げて閉じる。閉じ目の線は描いていない。
- 動きの量は、公式サンプルの頂点を公開APIで実測した比率を目安にした（`docs/reference-measurements.md`）。

再生成：`cd hv3/tools && npm install && node build-rig.mjs`。確認用の固定姿勢表示は `dev.html?view=bust&p={"EyeLOpen":0}`。

## パッケージの使い方（`hv3/hibiki-avatar.js`）
HUB・Twinow・オウンドメディアで共通に使う部品として、表示・視線・向き・動きの量・スクロール中の半透明・全身／バストアップの切り替えを1つの関数にまとめた。各サイトは設定を渡すだけで、見た目はCSSで上書きできる。

```js
import { mountHibikiAvatar } from './hv3/hibiki-avatar.js';
const avatar = await mountHibikiAvatar(document.querySelector('#avatar'), {
  view: 'bust',                 // 最初の表示：'bust'（バストアップ）／'full'（全身）／'face'（顔）
  chat: false,                  // true：チャットの中。バストアップに固定し、切り替えボタンを出さない
  viewToggle: true,             // 待機中のアバターの角（体・顔・手に重ならない角を自動で選ぶ）に「全身／バストアップ」のボタンを出す
  rememberView: 'hibiki-view',  // 選んだ表示を覚える localStorage のキー（false：覚えない）
  scrollFade: { enabled: true, opacity: 0.35, restoreMs: 600 }, // スクロール中の半透明：オン・オフ、透明度、止まってから戻るまでの時間（ミリ秒）
  motionSize: 'auto',           // 動きの量：'auto'（表示の大きさから自動）／0（大きい表示向け）〜1（小さい表示向け）
  facing: 'auto',               // 向き：'auto'（ページ上の位置から）／-1（左に置いた）〜1（右に置いた）
  autoplay: true                // false：step(dt) を呼ぶまで止めておく（試験や録画用）
});
avatar.motion.gesture('wave'); avatar.setState('happy'); avatar.motion.talk(2);
avatar.setView('full'); avatar.setScrollFade({ enabled: false }); avatar.setViewToggle(false); avatar.destroy();
```

- 表示の大きさと動き：アバターが描かれている高さが200 px以下で最も大きく、520 px以上でLive2Dの標準に近い量になる。方針「体で向けて、顔は正面寄り、目でこちらを見る」に合わせ、頭の動き（追従・待機中の揺らぎ・身振りに伴う頭の動き）は大きさで変えず、小さい表示では体の向き（範囲いっぱいの±10まで）・体の揺らぎ・身振りに伴う体の動き・揺れもの（揺れる幅）を大きくして伝える。頭の角度は髪の崩れが無いと確かめた±24の範囲に収める。
- 動きを減らす設定（prefers-reduced-motion）：自動デモを止め、待機中の揺らぎを半分、揺れものを控えめにする。
- スクロール中の半透明：ページ（またはスクロールする親要素）がスクロールしている間だけ半透明にし、止まって `restoreMs` 後に戻る。
- 全身／バストアップのボタン：選んだ表示を覚え、次に開いたときもその表示になる。保存できない環境（プライベートブラウズ等）では、その場の切り替えだけ行い、表示は壊れない。切り替えても、視線の追従と配置による向きはそのまま続く。
- CSSで上書きできる値（ホスト要素か、その親に指定する）：

| 変数 | 内容 | 既定 |
|---|---|---|
| `--hv3-scroll-opacity` | スクロール中の不透明度 | 設定の `scrollFade.opacity` |
| `--hv3-fade-out` | 半透明になるまでの時間 | `0.18s` |
| `--hv3-fade-in` | 元に戻るまでの時間 | `0.35s` |
| `--hv3-toggle-bg` ／ `--hv3-toggle-fg` ／ `--hv3-toggle-border` | ボタンの背景・文字・枠の色 | 白・紺・淡い灰 |
| `--hv3-toggle-radius` ／ `--hv3-toggle-font-size` ／ `--hv3-toggle-inset` | ボタンの角丸・文字の大きさ・右下からの位置 | `999px` ／ `13px` ／ `8px` |

ボタンには `hv3-view-toggle`、スクロール中のホストには `hv3-scrolling` のクラスが付くので、細かな見た目はこれらのクラスでも上書きできる（パッケージのCSSは `:where()` で詳細度0）。

## V2の感情表現の入力（`hv3/emotion.js`）
Twinow のコンパニオン（V2）と同じ入口・同じ形で状態と感情を受け取り、響V3のパラメータ（目・眉・口・笑顔・頭・体・肩・視線）のメッシュ変形で表す。画像の差し替えはしない。HUB と Twinow で分岐させない。Twinow 本体・HUB 本体のコードは変更しておらず、組み込みもしていない。

```js
avatar.setState('thinking', { duration: 0 });          // 本体の setState(state, options) と同じ
dispatchEvent(new CustomEvent('aifate:companion-state', { detail: { state: 'happy', options: {} } }));
dispatchEvent(new CustomEvent('aifate:companion-chat-lifecycle', { detail: { phase: 'complete', anchor: null, emotion: 'happy' } }));
avatar.chatLifecycle({ phase: 'complete', emotion: 'concern' }); // 同じ処理を関数で
avatar.setEmotion('sadness');  // 確認用：状態の感情を上書き（'auto' で状態に合わせる）
avatar.getSnapshot();          // { state, phase, emotion, history, speaking, … }
avatar.states;                 // 10状態
```

`listen: false` を渡すと window の合図を受け取らない（同じページに本体のコンパニオンがいるときなど）。未知の状態・値は無視して `false` を返し、表示は変えない。

### 状態ごとの表し方
感情の表は Codex の `studies/continuity/emotion.js`・`affect.js` と README の V2 の節を土台に、響V3のパラメータで作り直した。響は前髪が眉にかかるため、眉に頼らず、目の開き（`EyeLOpen`/`EyeROpen`、見開きの `EyeWide`）、口の形（`MouthForm`、すぼめ・丸めの `MouthPucker`、片寄せの `MouthShift`）、頭の傾き、体・肩の身振りで見せる。どれも画像の差し替えではなくメッシュの変形。見開き（`EyeWide`）は上まぶたを主に上げ、虹彩は見開きの変形の子にせず（白目でクリップするだけ）丸いまま残す。肩すくめ（`ShoulderUp`）は胴のワープで首の両脇の帯（襟から胸の上まで）を上げる。顔は正面寄りのまま、小さい表示ほど体と肩の動きを大きくする（最大 1.8 倍）。

| 状態 | 感情 | 顔 | 頭・体 |
|---|---|---|---|
| idle | smile（目の開き 1・目の笑い 0.55・口の形 1・開き 0.52） | 笑顔、上の歯が見える（下の前歯の先も薄く 1 列）。目は開いたまま | 待機の揺らぎ |
| attention | gentle | 目を少し見開き、口を閉じた穏やかな笑み、視線を正面へ | 一瞬前に乗り出して顔を上げる |
| thinking | thinking | 笑みを消し、口をすぼめて片側へ寄せ、目を細め、視線を右上へ | 首を大きくかしげ、少し引く。呼吸を浅く |
| speaking | smile | 笑顔で口の開け閉め（どの感情でも唇が閉じ切る。すぼめは話す間ゆるむ） | — |
| happy | joy | 目を細めた満面の笑み、口を大きく開ける | 体を反らせ弾むように揺れ、肩が開く |
| notify | surprise | 目を見開き（上まぶたが主に上がり、虹彩は丸いまま白目が上に見える）、口角を平らにして口を小さく丸く開ける（上唇が歯に少しかぶさり、口の中の暗さが見える）。0.5 秒保って落ち着く | 0.1 秒で頭を上げ肩をすくめ（`ShoulderUp`）、約 1 秒で戻る |
| concern | concern | 笑みを消し、口角を下げて横に引き、目を少し伏せる | 首を反対へかしげ、前かがみに傾け、肩をすぼめる |
| error | sadness | 口角を下げ、目を伏せて下を見る | うつむき、肩を落とす |
| sleep | neutral | 目を閉じ口を閉じる | うつむき、肩を落とし、呼吸をゆっくり |
| wake | gentle | 0.76 秒で目を開く | — |

本体の状態名と合図は変えていない（error は本体と同じく error として受け、表し方だけ sadness の顔と体を使う）。

確認ページの「状態」「感情」の行で各状態・感情を、「会話」の行でチャットの流れ（送信 → 考え中 → 話す → 完了の感情 → 待機）を、本体の conversation.js と同じ合図を送って再生できる。
