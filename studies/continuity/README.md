# 響V3：接続品質を優先した比較試作
## 2026-10-23：感情・閉口・デモ操作の回帰修正

`emotionfix-20261023`。前回は画像と一部の動作を確認しましたが、静止表示での感情切替と手動スライダー後の操作順を確認できておらず、不具合を見逃していました。

原因と修正：
- 静止表示が選択中の感情を無視して初期笑顔を描画 → 現在の感情を一度描き、変更時だけ更新。自動的な動作を再開しない。
- 手動の口・笑顔が感情選択後も残存 → 画面の感情選択で解除。V2状態プリセットは感情をautoへ戻す。APIの状態と感情の独立指定は維持。
- 口を0にしても笑顔の開口下限が優先 → 明示された口入力は0を含めて反映。sleepは閉口を優先。
- 中立メッシュに開口の隙間が残り、丸口キーも独立に口を開けていた → 接触線を閉じ、開口はmouthへ一本化。閉口時の歯・舌描画を抑止。
- デモ中も口スライダーが旧値を表示 → 実描画値へ同期。デモからタップ操作へ移るときも発話フラグを解除。

|感情|発話していないときの口|
|---|---|
|中立・微笑み・困惑／心配・悲しみ・思考・照れ・怒り|閉口|
|笑顔・喜び|自然な歯の見える笑顔|
|驚き|小さな開口|

発話・音量入力中は各感情のまま開閉し、休止で閉じます。音声なしオートデモは疑似発話であり、音声への同期ではありません。実際の口開度とスライダーの同期、心配／悲しみ／思考区間の閉口を一巡で検証。

[各感情と閉口の実描画](evidence/emotion-controls.png)／[操作・デモの記録](evidence/emotion-controls.json)。PC Chromeの390pxタッチ再現であり実機スマホではありません。新規画像生成・右腕の変更はありません。
## 2026-10-23：歯列・唇・口角を一体として再制作

笑顔の上下唇と口内を分離。歯列は上顎側の形を保ったまま、動く開口マスクで隠します。唇は接触線へ形状補間し、口角・頬・下まぶたの既存連動を維持。中央と側方の歯の幅・長さ・陰影差、唇の丸みを素材側で制作しています。表情完成画像を切り替える仕組みではなく、局所素材のメッシュと遮蔽を動かします。

[拡大比較](evidence/mouth-transition.png)で笑顔・閉口・発話途中・斜め・中立・中間表情を確認し、閉口時の白線と中間状態の二重歯列を修正。V2状態、音量同期、スマホ幅、デモも確認します。実機スマホと人間による自然さの受入は別です。右手の挨拶は今回変更していません。

制作方法・プロンプトは [smile-local.json](materials/smile-local.json)。大きな口の開きや母音ごとの立体的な唇形状は今後の調整範囲です。

## バストアップ全体の連動（2026-10-22）

目的は既存の顔・視線・表情を保ちながら、胸郭・両肩・首・頭・右腕を共通の座標と動作意図で結ぶことです。対象はこの独立プレビューの基本構造・複合動作・公開まで。全身化、左手の新ジェスチャー、衣装交換素材、利用先との統合は今回の対象に含めません。

`bust-rig.js`で root→thorax→肩／首→頭→眼・口・髪、および右肩→上腕→前腕→手の関係を定義しています。腕の親座標は胸郭の回転・姿勢・呼吸・肩の上げ下げを継承し、上腕の共有表面と前腕・手で同じ親変換を使います。予備動作と体幹の小さな支え、肩周辺の手作業の補正ケージを合成し、顔の局所形状キーや接合境界を変えずに複合動作を評価します。髪の二次動作は頭・身体の変化を入力とする制限付きばねで、固定した小刻みの時間積分と長時間停止からの復帰リセットを備えます。

既存調査から応用したのは、ケイの「呼吸の親の下に肩・首・身体を置く階層」「局所形状と接合の分離」、公開サンプルの頭＋身体を入力にした物理・表情と発話の分離という原則です。ケイのEditor直接観察と、Izumi／Haru／まおの公開設定調査を同じ解析範囲とは扱いません。非公開Coreやサンプルの形状・物理定数は移植していません。今回新しいREA内部解析は実施していません。

[複合姿勢](evidence/bust-composite.png)／[暗背景の首・襟](evidence/bust-neck-dark.png)／[検証記録](evidence/bust-verification.json)。PC Chrome・スマホ幅タッチ再現による確認であり、実機スマホや自然さのHuman Acceptanceではありません。画像素材は追加せず、肩の補正データと独自の共通制御を追加しています。肘は画角外、独立した大きな髪束・奥行きの腕のひねり・手の表裏・衣装交換用の隠面素材は未制作です。

## 原因と修正

1. **元画像はつながっていても、切り出した画像のα合成はつながらなかった。** `build_anatomical.py` の顔・首マスクは、それぞれをぼかしてから別画像に適用します。補完するαがaと1−aでも、通常のsource-over合成の被覆率は `a + (1-a)^2` で、完全な不透明にはなりません。髪にはY=782等で切断した領域もあります。切断部のテクスチャ補間・独立した変形も隙間の要因です。
2. **実描画でも正面時の欠損を確認。** 元画像でα>240の画素に限ると、旧描画の首領域では1,100画素、髪の切断位置付近では344画素に20以上のα低下がありました。新方式の同じ正面領域では該当画素は0です。[領域・結果](evidence/alpha-comparison.json)。これは当該領域の透過欠損の証拠で、自然さの合格値や全姿勢の保証ではありません。
3. **身体変形を増幅しても、人物としての構造にはならなかった。** 旧版は推定奥行き投影、7×7身体変位、肩の回転、表情の式を重ねます。衣装画像には首・襟・ネクタイ等が重複し、別々の画像を動かすと下の写真が露出します。衣装JSONのcorrections／occlusionも現在の描画器では評価されていません。異なる領域を同じ変位で動かしても、造形や描画順の問題を解消できるとは限りません。
4. **今回は顔・首・髪・スーツの接続部を切断しない表面に変更。** 胸→首→頭の親子変換と連続したスキニング重みで共有頂点を動かし、腰側を固定します。別画像の重ね幅やぼかしで首の隙間を隠す処理ではありません。頭の追従・呼吸は正面寄りの小さな範囲に限定しました。大きな3D風の顔向きの代替ができたという主張ではありません。
5. **口は接触線に沿ったメッシュの開口。** 上下唇は周辺の顔表面に連続したまま、口の境界を開きます。奥に口内の下地を置き、単なる黒い矩形の貼り付けや口画像の切替ではなく、開口形状で遮蔽します。
6. **まぶたに沿う頂点と、閉眼時の材質が必要だった。** 最初の均等格子では閉眼後も眼が残りました。上・下まぶたの輪郭へ頂点を配置し、形状キーと開口マスクを対応させました。さらに既存の許可済み閉眼画像から眼周辺だけを取り、閉眼形状に対応するUVへ補正した材質を制作しました。閉眼近傍でのみ合成し、潰れたまつ毛が二重になる問題を抑えます。顔全体の写真を差し替える方式ではありません。
7. **虹彩素材にまつ毛が焼き付いていた。** 元の虹彩パーツには上まつ毛も含まれていました。隠れる虹彩上部を自身の下側から補い、動く白目の開口に沿ってマスクし、視線移動でまつ毛まで移動する問題を抑えました。補完部分は推定の作画で、測定された眼球ではありません。

## 素材制作と自動操作

前報のPhotoshop CC 2018／19.0とIllustrator CC 2018のCOM失敗 `0x80080005` を再利用し、同じ失敗を繰り返して制作を停止する方針は取りませんでした。

- [drmedia/photoshop-mcp](https://github.com/drmedia/photoshop-mcp)：MIT、Photoshop 25.0以上、検証27.8。19.0には適合しません。
- [francisanderson/photoshop-mcp](https://github.com/francisanderson/photoshop-mcp)：MIT、PS2020/v21.2で検証、COM→ExtendScript経由。旧版にも対応するという記載はありますが、19.0での実接続や現在のCOM失敗の解消は未確認です。
- [BunsDev/adobe-mcp](https://github.com/BunsDev/adobe-mcp)：MIT、Windows／COM・ExtendScript。READMEの対象はPS2026等。CC2018での動作確認・全コードの安全性監査はしていません。

これらは非公式の候補であり、安全性・互換性を確認済みと称して追加しません。任意スクリプト実行を含む強い操作面があるため、不要なサーバー・権限・設定を追加せず、今回はローカルCanvasの素材制作コードとag-psdで実制作しました。**今回Adobeを操作してPSDを作ったという報告ではありません。**
