# 響V3：Desktop参照モデルの構造解析

2026-10-25 / Codex / 実装・Live2D構造解析

## 判断

破綻を抑えるには、独立した完全な素材面、変形の役割を分けた親子階層、接合部の重なりと描画順、必要箇所の非線形な形状補正を同時に成立させる必要がある。パーツ枚数や参考モデルの階層名だけを合わせても品質は保証できない。以下は実データと画面で確認した事実、それを踏まえた響への設計判断であり、響の完成検証ではない。

## 調査範囲と証拠

- Desktopの編集モデル9件を列挙しSHA-256を記録。Kei基本/母音、Haru、Izumi4種、Mao、Natori。
- 配布ZIPの実行モデル6組とSDKサンプル8組、計14組を列挙。MOCの異なるハッシュは13。名前が同じでも同一モデルと決めつけない。
- 14組を公式SDKで読み込み、基準値・顔の左上・顔の右下（対応パラメータのみ）の実画像を取得。全公開パラメータを個別に最大値へ動かしたメッシュ変位、親パーツ、クリッピング参照を記録。
- Renは旧Coreで `Official Core did not load model`。公式Core5.3とFramework5-r.5を解析専用に分離して復旧し、198メッシュ・73パラメータを取得。基準・左上・右下＋開口の異なる実画像と拡大画像を確認した。旧ビュー解放処理の失敗がRice/Wankoに連鎖した問題も、各モデルを独立ページで読み込むことで除去した。
- `all-runtime-analysis.json`、`structure-comparison.json`、`all-models-poses.jpg`、`all-models-first-atlas.jpg`。
- 編集階層は公式Editor + DPI対応PrintWindowで確認。SDKでのメッシュ変位から編集デフォーマやGlueの有無を推定確定しない。
- 参考モデルの原ファイル・響PSD/モデルは保存・上書きしていない。新たな素材生成は行っていない。
- 編集モデル9件すべてをEditorで参照。Kei基本・Haru・Izumi4種・Mao・Natoriは展開した階層を先頭から末尾まで画面記録し比較した。Kei母音版は髪の階層と公式APIの口形キーを確認し、基本版とruntimeメッシュ・マスク構成を比較した。各ノードの全キー形状を列挙検証した意味ではない。
- 14組の全テクスチャ22ページを確認。第1ページ一覧に加え、`remaining-atlases.jpg` に残る8ページを記録。原画像は公開Gitへ再配布しない。
- `source-preservation-check.json`：Desktopの9編集モデル全件のSHA-256が調査前と一致。

## 確認した構造と響への適用

### 顔・目・口

- Keiの顔肌、耳、眉、眼球、まぶた、鼻、唇、歯、舌は別素材。左右の目は各9メッシュ、眼球側は各3メッシュ。眼球と2つのハイライトを白目形状にクリッピングしている。
- Kei Editorでは顔の曲面の下に顎の曲面、口の曲面の下に舌の曲面がある。鼻は線・影・ハイライトに分かれる。顔全体と局所動作を分担する構造が確認できるが、各ノードの全キー割当までは未検証。
- Kei母音版では口開閉は通常パラメータ、A/I/U/E/OはType1で0/1キー。基本版とメッシュ数が同じでも制御構成が違う。
- Haru Editorは口の曲面の下に口内の曲面、左右眼球の位置の下に上下ハイライトの別曲面を持つ。眉は曲面→位置→角度の階層。配布版はマスクなしでも目周囲の独立素材と変形で成立させているため、クリッピングだけが唯一の解法ではない。
- Maoは口9メッシュ中3メッシュにクリッピング、眼球10メッシュ全てにクリッピング。歯・舌を口外に出さない処理を、単なる画像一括変形と区別する。
- 響への判断：顔の肌面を完成した連続面として作る。目素材に髪を混ぜない。目の開口、眼球、まぶた、周囲の肌、口内の遮蔽を個別に成立させる。原画Aの目鼻口・輪郭を変えて部品不足を吸収しない。

### 髪

- Kei基本版の実編集階層は前髪1、左右横髪各2、後ろ髪1、襟足1の7領域。各領域に曲面→曲面Z→ふわ→揺れ→メッシュの段階がある。顔の回転に追従する親と局所の揺れを分離している。
- Kei後ろ髪ArtMesh47は描画順500、クリッピング欄空。メッシュは顔の後ろまで覆う。さらにテクスチャ上で後ろ髪が頭全体を覆う面を持つことを確認した。メッシュの面積と不透明テクスチャの面積は別に評価する。
- Haruは後ろ髪の曲面と頭頂部の曲面、左右後ろ髪、左右横髪、前髪を区別。前髪は曲面→角度Z→揺れ。Keiと全く同じノード構成ではない。
- Hiyoriの公開パーツ名には左右前髪のスキニングがあり、各7メッシュ。Riceは後髪A/B/Cが7/9/9、左右横髪が各5メッシュのスキニング領域。これは公開パーツ名と実メッシュ数の確認で、編集ボーン階層を復元した意味ではない。
- 響への判断：頭皮側の被覆・毛束の根元・表に出る毛先を別の責務として設計する。短い毛束へ長髪用の分節を無条件に増やさない。顔向きで現れる隠れ面を先に描き、根元が浮かず毛先が追従する変形を後に設定する。現在の5枚分割だけではKei同等とは言えない。

- Renのruntimeでは前髪5、後ろ髪11、別の髪影、首2、口7、身体の左右腕各8とジャケット袖各2を確認。さらに描画順用の左右腕群各10がある。24オフスクリーン領域中4領域にマスクがあり、通常メッシュのマスク4件だけでは遮蔽全体を説明できない。名称が同じ親パーツも別IDのため混同しない。

### 首・身体・衣装

- Keiの首曲面には襟・首・襟後ろが所属する。体の曲面Z→Y→呼吸の下で首と身体を分ける。
- Haruは呼吸の下で胸部・胸の揺れ・スカート・足と首を分け、衣装1/2に別素材と曲面を持つ。Editorでは実行用Pose適用前の腕A/Bが同時に見えるため、Editor基準表示だけを最終描画と見なさない。
- Izumiアニメ版・厚塗り版は体Z→体Y→呼吸→首回転→首曲面→追加首曲面、顔回転という構造。衣装は服の曲面に襟・胴体などをまとめ、左右腕は独立した回転階層。髪影と顔横影も独立している。塗り方の違いで鼻・目の補助メッシュは変わる。
- 響への判断：首の上端を顔の下へ、下端を襟と胴体の下へ覆わせる。襟前・襟後・袖・袖口・肩周囲を素材として分離し、着衣状態で皮膚が意図せず露出しない重なりを先に作る。身体と衣装の独立を維持する。

### 腕・手・指

- Haru Editorは左右A/Bの位置XZ→上腕回転→前腕回転→手首回転という階層。各衣装に別の腕素材があり、腕組みと腕下ろしは別素材群。runtimeのPose2群でも確認できる。
- Maoは左右A/Bが別パーツ群、先行の公式Editorキー記録に肩・肘・手首の独立制御がある。Natoriは腕A/B/C/D/Eと6種類の手袋群、前腕群を持つ。Pose差分と連続関節運動を混同しない。
- 今回のMao Editor実画面で、肩すくみ→腕位置→上腕回転→前腕回転→手回転、前腕の局所曲面を確認。右Bには袖裏・人差し指裏が別メッシュであり、左Bには人差し指の独立回転がある。隠れ面を素材から作る根拠になる。
- 今回のNatori Editor実画面で、体の前後・呼吸・腰Z・肩上下・肩位置・肩回転・肘回転・手首回転を段階化し、袖の曲面・袖裏・腕裏・掌と指を分けていることを確認。右手05の指曲げ3系統は各0/15/30キー。右腕Aの肘は-40/-20/0/10、左腕Aは-40/0/10。中間形状と左右差を一律の回転規則へ潰さない。
- Markは左右腕各1メッシュの単純な構造。Wankoは動物と器のモデルで、人間の手の立体造形の根拠にはならない。
- 響への判断：肩・上腕・肘・前腕・手首・掌・指の責務を分ける。袖口と手首の奥、指の付け根、指間、掌の側面の素材を用意する。参考群の手差分だけで響の30指関節の連続可動を検証済みとは言えない。掌と指の側面は響自身の可動で追加検証が必要。

## 響へ反映する構造設計

既存の仕様範囲で、次の責務を素材と可動に分けて対応させる。参考モデルのノードをそのまま複製する指示ではない。

1. 身体：全体位置・姿勢 → 胴体の向き → 呼吸 → 肩の上下。首と腕と着衣をここから適切に分岐させる。
2. 頭：首の位置・曲面 → 頭の回転 → 顔の立体形状。顔肌・顎・目・眉・鼻・口・耳を局所調整可能にする。首は顔と襟の両方の奥に素材が続く。
3. 髪：頭部追従 → 向きによる形状 → 毛束の厚み → 局所揺れ。前・横・後・襟足の役割を用意し、根元と頭皮被覆を確保する。髪影は顔肌や目素材に焼き込まない。
4. 目：目の立体位置 → 開閉する目の開口 → 白目による眼球の表示範囲、眼球位置・ハイライト、上下まぶた・周辺肌。閉眼時も毛髪・白い穴・不自然な肌の縁を残さない。
5. 口：口全体の向き → 唇と口形 → 口内・歯・舌の遮蔽。開口量だけで発話を代用せず、必要な口形を形状として持たせる。
6. 腕：肩 → 上腕 → 肘 → 前腕 → 手首。回転の下に肘の膨らみ・袖口の局所形状を置く。素材は肩の奥、肘内側、袖裏まで完成させる。
7. 手：原画Aに近い掌と指の比率を保ち、掌・母指球・各指の接合側と隠面を用意。30指関節は、手差分の表示キーとは別に、連続動作として形状と遮蔽を検証する。
8. 衣装：身体とは独立した素材を維持し、襟前/奥、肩口、袖、袖口表/裏、胴、裾を対応する身体運動へ追従させる。着せ替え時にも身体の被覆が途切れない構成にする。

## 残存する検証限界

- Renの形式不一致は解消。旧Core数値版83951616はMOC5まで、新しい公式Core100663297はMOC6まで対応。公式配布 https://www.live2d.com/sdk/download/web/ と公式Framework5-r.5を使用。新版ではWebGL2・描画寸法・シェーダー読込待ち・ID文字列APIへの対応が必要だった。初回の同一姿勢画像は不採用とし、修正後の3画像SHA差・入力値・73個のID一意性を確認した。Core・Editorの改変、モデル変換、既存環境の上書きはしていない。Renの編集CMO3はDesktopにないため、編集デフォーマの内部構造を確認済みとはしない。
- 各編集ノードの全キー形状、全ポーズ・全複合値の無破綻を保証したものではない。今回の全身縮小画像は微細な隙間の証明に使わない。
- 参考モデルの腕や手の差分は、響の30指関節・掌側面・高角度複合姿勢の完成証明ではない。採用構造を響自身の素材と実表示で検証する必要がある。
- 響への適用は既存HV3-03〜07内の素材・構造修正とし、新仕様・追加Blockにしない。

## 証拠の保管

編集画面・参照テクスチャ・実描画画像はローカル解析フォルダに保管し、公開Gitには原モデルや素材を再配布せず、比較結果・集計・検証限界を記録する。14組すべてを解析したことは、全パラメータの最小値・全組合せ・全キー形状の無破綻保証を意味しない。
